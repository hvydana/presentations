      Most LLM cost overruns don't come from the model itself, they come from how it's called. A prompt that looks harmless in a demo often carries far more context than it needs, gets sent synchronously when it could wait, and returns more tokens than the task requires. None of that shows up until the bill does. The fixes tend to fall into a few buckets. 1. Model side: Route simple requests to smaller models and reserve frontier models for genuinely hard reasoning, and consider quantized or fine-tuned smaller models for narrow, repeated tasks instead of long prompts every time. 2. Prompt side: Cache repeated context instead of resending it, cap output length so generation doesn't run longer than needed, and periodically audit context windows so old conversation turns get summarized rather than carried forward in full. 3. Infra side: Batch non-urgent workloads, push tolerant tasks to async queues instead of paying for real-time latency, and stream responses so perceived speed goes up and retries go down. 4. Governance: Rate-limit high-cost users before they become a pattern, and track spend by feature and team so you know where the money is actually going before you start optimizing. If I had to point a manager and a coder at one thing each to start with, it wouldn't be the infra changes, those need buy-in and testing cycles. For managers: get cost attribution in place first. Spend broken down by feature, user, or team usually surfaces the real offender within a day, and it turns "let's optimize AI costs" from a vague directive into a specific, fundable fix. For coders: capping output length and caching repeated prompt context are the two changes you can ship this week with no architecture rework and no quality tradeoff.
