\begin{abstract}
\noindent
Voice AI has crossed from novelty to critical enterprise infrastructure.
The global AI voice-agents market reached \$2.4\,billion in 2024 and is
projected at \$47.5\,billion by 2034 at a 35\% CAGR.  Venture-capital
funding into voice AI reached \$2.1\,billion in 2025---eight times the
2022 level.  This article provides a comprehensive techno-business analysis
across six dimensions: (1) the five-layer technology stack (telephony,
ASR, LLM, TTS, orchestration); (2) cost anatomy for managed versus
self-hosted deployments; (3) the open-source stack and its gaps; (4) ASR
accuracy realities for Indian-language and telephony-quality audio;
(5) AMD's hardware competitive position with a 25--40\% cost advantage on
LLM inference and a 192\,GB HBM3 memory advantage on the MI300X; and
(6) India's structural position as the second-largest voice AI startup
ecosystem globally, where on-premise AMD hardware is simultaneously
cost-optimal and compliance-mandated under the DPDP Act.  Beyond the core
stack, the article maps the geographic opportunity across seven regions,
examines the three orchestration frameworks that every production voice AI
company converges on, and identifies AMD's specific gaps---from missing
Docker containers and PyPI packages to absent ISV integrations and
industrial edge hardware---versus NVIDIA's NIM ecosystem strategy.
Conservative modelling estimates that voice AI could reclaim 3.75 billion
work-hours annually in India alone, translating to approximately
\$1.1\,billion in economic value.
\end{abstract}

\section{Technology Stack}
\label{sec:stack}

A voice AI system is a five-layer pipeline (Listing~\ref{lst:pipeline}).
Each layer has its own latency budget, cost structure, and vendor ecosystem.

\begin{lstlisting}[caption={Five-Layer Voice AI Pipeline},label=lst:pipeline,
                   basicstyle=\ttfamily\scriptsize]
User speaks  (phone / browser / mic / WhatsApp)
                      |  raw audio
                      v
LAYER 1: Telephony / Transport
  Routes audio; handles SIP, WebRTC
  Vendors: Twilio  Telnyx  LiveKit  Plivo  SignalWire
                      |  PCM audio stream
                      v
LAYER 2: ASR / STT  -  "The Ears"
  Converts speech -> text  (<150 ms)
  Vendors: Deepgram  AssemblyAI  Whisper  Sarvam Saarika
                      |  transcript text
                      v
LAYER 3: LLM / NLU  -  "The Brain"
  Understands intent; generates reply
  Vendors: GPT-4o  Claude  Gemini  Llama 3  Mistral
                      |  response text
                      v
LAYER 4: TTS  -  "The Voice"
  Converts text -> natural audio  (<150 ms)
  Vendors: ElevenLabs  Cartesia  Kokoro  Coqui XTTS-v2
                      |  audio stream
                      v
LAYER 5: Orchestration  -  "The Conductor"
  VAD, turn-taking, context, routing
  Vendors: Vapi  Retell AI  Pipecat  LiveKit Agents

\subsection{Layer 3: LLM / NLU}

LLM inference is the \emph{cheapest} layer per minute for most voice AI
systems: a system running 10{,}000\,min/month spends under \$200 on the LLM.
What matters is latency.  LLMs must return first tokens in $<$200\,ms;
smaller models (Llama~3.1~8B, Mistral~7B) are often preferred over larger
ones for voice.

\paragraph{The Hinglish problem.}
Most Indian professional phone calls involve code-switching mid-sentence
(e.g., \textit{``haan aapka order Bandra mein deliver hoga next Tuesday
ko''}).  Whisper's language detection resets at segment boundaries, causing
errors on code-switched audio.  India-tuned models (Sarvam Saarika, Gnani
ASR) handle this natively.

\paragraph{Whisper hallucination risk.}
An ACM FAccT 2024 study documented Whisper fabricating content during
silences.  Hallucination rates range 1--80\% of segments depending on
conditions \cite{vexascribe-wer}.  Mitigation: Silero VAD to gate ASR input;
Calm-Whisper for silence-aware handling.

\subsection{LiveKit Agents (Apache 2.0) --- The WebRTC Backbone}

LiveKit is the open-source WebRTC stack that OpenAI's ChatGPT Voice Mode
runs on.  Character.ai, Meta, and thousands of production voice products use
it.  LiveKit Agents 1.5.x is current as of April 2026.

An agent joins a ``room'' as a headless participant, subscribes to the
caller's audio track, runs it through STT, feeds text to an LLM with
tool-calling, and publishes synthesised speech back.  Native SIP and phone
numbers shipped in 2025---no Twilio bridge needed.  Multi-participant native;
Model Context Protocol (MCP) built in; entire media server + Agents SDK is
Apache 2.0.

\textbf{AMD angle:} LiveKit handles network.  The GPU is needed for the
model layer.  If STT, LLM, and TTS models run on AMD GPUs, AMD becomes the
compute substrate for every LiveKit deployment.

\subsection{Pipecat (BSD-2) --- The Model Integration Layer}

Pipecat is a Python framework from Daily.ai that reached v1.0 in April 2026
with 60+ service connectors covering every STT, LLM, TTS, and transport
combination.  Architecture: left-to-right frame pipeline---each audio frame
flows through VAD $\to$ STT $\to$ LLM $\to$ TTS $\to$ output.  Each stage
is a swappable component.

\textbf{AMD angle:} Pipecat is transport-agnostic; pure Python, pure PyTorch
under the hood --- ROCm compatibility is direct.  Its self-hosted model
support (Ollama, vLLM, local Whisper) is exactly the AMD deployment scenario.
\texttt{pipecat create} scaffolds a working agent in under 60 seconds ---
AMD needs to be the compute target when that command runs.

\subsection{TEN Framework (C++ / Go / Python) --- The Performance Core}

TEN (Transformative Extensions Network) is the highest-performance framework
because its core is C++.  It includes proprietary VAD and turn-detection
models optimised for sub-300\,ms response.  TEN is where avatar + voice
combinations run (Trulience, HeyGen, Tavus lip-sync integrations).  Requires
Docker + Agora account.

\textbf{AMD angle:} TEN's C++ compute core calls the GPU driver directly.
A ROCm-certified TEN container would validate AMD for the
highest-performance tier.

\subsection{How NVIDIA Became the Hardware Gateway --- The NIM Playbook}

NVIDIA won voice AI not by making better silicon alone, but by making their
silicon the \emph{path of least resistance} for every developer.  The NIM
(NVIDIA Inference Microservices) strategy:

\begin{enumerate}[noitemsep]
  \item \texttt{docker pull nvidia/riva-asr} --- Parakeet TDT, production-ready, CUDA-optimised, one command.
  \item \texttt{docker pull nvidia/riva-tts} --- Maxine Studio Voice, same one-pull model.
  \item \textbf{AI Blueprints} --- complete, working voice agent applications; developers clone, not design.
  \item \textbf{RTX Spark} (Grace + Blackwell, 128\,GB shared memory) --- entire large models in shared memory; no bottleneck.
  \item \textbf{VS Code NIM extension} --- the tool every programmer uses defaults to NVIDIA compute targets.
  \item \textbf{Azure AI Foundry} native NIM (July 2026) --- deploy from VS Code, one click, NVIDIA GPU underneath.
  \item \textbf{28 million developers} who downloaded NIM opted into the NVIDIA ecosystem by default.

\label{sec:ecosystem}

Beyond the three frameworks, NVIDIA has staked out positions across five
distinct ecosystem layers.  Each layer operates on the same logic: ship a
named package or container; let developers adopt it as the default; AMD
silicon becomes invisible at the call site.

Every LangChain or LlamaIndex voice agent that uses NIM routes to NVIDIA

AMD does not exist in that call.

\subsection{Layer 2 --- Inference Serving Infrastructure}

\textbf{NVIDIA Triton / Dynamo-Triton} is the invisible substrate beneath
every production voice pipeline.  ASR, LLM, and TTS models all serve from
Triton.  Users include Microsoft, American Express, Salesforce, Hugging
Face.  In March 2025 NVIDIA folded Triton into \textbf{NVIDIA Dynamo} with
disaggregated LLM serving (prefix caching, KV offload to storage).

\textbf{TensorRT-LLM} sits on top: at batch size 1--4 (real-time voice),
TensorRT-LLM holds 20--30\% throughput advantage over vLLM ROCm.  A 50\,ms
difference in LLM token generation is audible to a human ear.

AMD's position: vLLM ROCm became first-class in January 2026 (CI pass rate:
37\% in November 2025 $\to$ 93\% six weeks later; first pre-built Docker image
shipped).  But vLLM is one serving tool.  There is no AMD model-serving
standard, no AMD inference server with multi-model ensemble orchestration,
no Dynamo equivalent for AMD.

\subsection{Layer 3 --- Voice-Domain SDKs}

\begin{enumerate}[noitemsep]
  \item \textbf{NVIDIA Riva:} Full conversational AI SDK --- ASR + TTS + NMT + diarisation + speaker ID + VAD, served as gRPC microservices.  Fine-tunable via NeMo.  Supports English plus Hindi, Arabic, Mandarin, Spanish, and others.  Real-world: Caterpillar's Cat AI Assistant runs Riva on Jetson Thor inside bulldozers (offline, no cloud).  \textit{AMD alternative: stitch Whisper + Coqui TTS + pyannote manually; no enterprise SLA, no unified API.}

  \item \textbf{NVIDIA Maxine:} Real-time noise suppression, acoustic echo cancellation, room reverb removal.  Used in Cisco and Zoom.  In a noisy call center, noise suppression before ASR is the difference between 10\% WER and 25\% WER.  \textit{AMD alternative: none.}

  \item \textbf{NVIDIA ACE (Avatar Cloud Engine):} Riva + Audio2Face (lip sync from audio) + Nemotron LLM + P-Flow voice cloning, all as NIM microservices.  Deployed in customer service kiosks, retail concierges, healthcare reception, and gaming NPCs.  \textit{AMD alternative: none.}
\end{enumerate}

A bank branch digital concierge on ACE is locked to NVIDIA at every layer
--- not by contract, but by absence of AMD-equivalent components.

\subsection{Layer 4 --- Edge Hardware}

\textbf{NVIDIA Jetson:} Jetson Nano ($\sim$\$100) through Jetson AGX Orin
(64\,GB, 275\,TOPS) to Jetson Thor (241\,TOPS with MIG).  JetPack OS ships
with Riva, vLLM, NemoClaw agentic framework, and full CUDA stack.  Certified
OEM partners: ADLINK, Siemens, KUKA.  \textit{Example:} Cat AI Assistant on
Jetson Thor + Riva ASR + Qwen3~4B via vLLM inside a bulldozer cab.  Offline,
no latency, full privacy.

\textbf{AMD answer:} Ryzen AI NPU runs Whisper BFP16 on a laptop.  It works.
But there is no industrial edge module, no JetPack-equivalent OS image, no
certified hardware partners for robotics or kiosk deployment.  Ryzen AI NPU
addresses the developer laptop; Jetson addresses every physical deployment
at the edge --- different markets, only NVIDIA present in physical
deployment.

\section{The Four Upstream Gaps}
\label{sec:upstream}

Sections~\ref{sec:frameworks} and~\ref{sec:ecosystem} map downstream gaps:
framework plugins, serving containers, marketplace slots, and edge hardware.
Those are real and closeable.  But four upstream gaps operate at a different
layer---before a model is deployed, before a developer picks a framework,
and before an enterprise issues a purchase order.  Closing only downstream
gaps puts AMD in the running for inference workloads.  Closing upstream gaps
creates platform momentum.

\subsection{Gap 1 --- Training and Fine-Tuning Moat}

Voice AI companies fine-tune continuously on proprietary data: custom ASR
acoustic models on customer speech (medical, legal, financial), custom TTS
voice clones, custom NLU models on domain intents.  This fine-tuning loop
runs weekly or monthly through NVIDIA-anchored tooling.

\textbf{NVIDIA NeMo} provides training and fine-tuning recipes for ASR
(Conformer, Parakeet), TTS voice cloning (FastPitch, HiFi-GAN), and LLM
instruction tuning---all with Triton export as the final step.  A company
that fine-tunes Riva ASR using NeMo gets a TensorRT-optimised artifact
deploying directly to Triton.  The entire pipeline from raw audio to
production microservice is one command.

\begin{table}[H]\centering
\caption{Critical Library Gaps on AMD ROCm (Training / Fine-Tuning)}
\label{tab:lib-gaps}
\begin{tabularx}{\textwidth}{llX}
\toprule

\texttt{bitsandbytes} & Most-used quantisation lib (4-bit, 8-bit) & No official support --- community fork only \\

The consequence: a company that fine-tunes ASR using NeMo will not switch
GPU vendors for inference.  The model's artifact, quantisation format, and
deployment recipe are NVIDIA-native.  Re-running fine-tuning on AMD requires
porting the recipe, validating outputs, and re-benchmarking---cost with no
revenue upside.

\textbf{What AMD needs:} Official ROCm support in \texttt{bitsandbytes}
(community fork engineering work already exists); a NeMo-equivalent speech
training framework or certified NeMo-ROCm Docker image; FlashAttention 3
port or competitive CDNA3 replacement kernel.

\subsection{Gap 2 --- ISV and SI Sales Channel Moat}

Enterprises buy voice AI through independent software vendors (ISVs) and
deploy through systems integrators (SIs).  The GPU is chosen implicitly by
the ISV's architecture decision, made years before enterprise procurement.

\textbf{ISV integrations NVIDIA holds in voice AI:} Genesys (11{,}000+
enterprise customers; GPU-backed real-time agent assist); Salesforce Einstein
Voice; Cisco Webex (NVIDIA Maxine noise suppression baked in, not a feature
toggle); ServiceNow Now Assist; Five9, NICE CXone, Avaya.

\textbf{SI certification moat:} NVIDIA has formally certified TCS, Infosys,
Wipro, Accenture, and Capgemini as NIM implementation partners.  Their
engineers are trained on NVIDIA tooling; delivery playbooks reference it;
pre-sales demos run on it.  A client asking for AMD requires the SI to
rebuild its practice from scratch.

\textbf{What AMD needs:} Three to five direct ISV integration partnerships
(Genesys is highest leverage); an SI certification program equivalent to
NVIDIA's NIM partner program.

\subsection{Gap 3 --- Voice Plus Vision Convergence}

The next generation of deployed voice AI agents---retail kiosks, factory
copilots, healthcare reception, in-vehicle assistants, delivery
robots---combines voice with vision.

NVIDIA's unified multi-modal stack on Jetson Thor: Isaac (robotics vision),
Metropolis (video analytics), Riva (voice), ACE (avatar), and Cosmos (world
model for synthetic data), all on one CUDA substrate.  A Siemens factory
copilot combines machine-vision anomaly detection with natural-language
operator guidance using the same stack.

When voice AI companies grow their product to include a camera---and they
will, because vision context dramatically improves voice agent responses---they
stay on NVIDIA because AMD has no landing zone.  AMD has Instinct MI300X
(data center inference, no vision pipeline), Ryzen AI NPU (laptop, no
industrial form factor), and Radeon GPUs (separate driver stack, not
integrated with ROCm).

\textbf{What AMD needs:} A Jetson-equivalent embedded AI module with a
unified SDK bridging voice and vision on a single AMD device.  This is a
2--3 year hardware roadmap decision, not an engineering sprint.

\subsection{Gap 4 --- Synthetic Data Pipeline for Low-Resource Languages}

Training high-quality ASR for low-resource languages requires synthetic
speech data.  Real transcribed audio in Hindi, Bengali, Tamil, Swahili, or
Filipino is scarce---not because languages are rare, but because the
recording and transcription infrastructure has never been systematically
built for these markets.

\textbf{NVIDIA's answer:} The Nemotron synthetic data pipeline generates
diverse high-quality synthetic speech including varied accents, speaking
rates, and background conditions.  Sarvam AI, Gnani.ai, and AI4Bharat (IIT
Madras)---the three organisations building India's language model
foundation---all trained on NVIDIA DGX clusters using NVIDIA-native pipelines.

\textbf{The data flywheel:} NVIDIA's synthetic pipeline feeds training
$\to$ better models $\to$ more voice AI companies $\to$ more fine-tuning
data $\to$ better models.  AMD is not in this loop at any point.

\textbf{What AMD needs:} An AMD-sponsored voice data initiative for
high-priority markets --- partnership with AI4Bharat or similar to fund
transcription and annotation of 10{,}000+ hours per language, with AMD
compute provided for training.  Cost: approximately \$2--5M in compute
credits and \$3--8M in data collection over two years.  Return: model
ecosystem that is AMD-native from inception.

\section{Conclusion}
\label{sec:conclusion}

Voice AI has become essential infrastructure.  The five-layer stack is
standardising.  The India opportunity is massive, unique, and structurally
underserved.  The geographic analysis confirms that compliance-mandated,
cost-sensitive on-premise deployments cluster in exactly the markets where
AMD's hardware economics are strongest: India, the Middle East, and Europe.

NVIDIA owns training and the current ecosystem.  CUDA's 15-year head start
in tooling, documentation, and production confidence is real.  For teams
without capacity to adapt, CUDA remains the default.  But
inference---the workload that runs 24 hours a day serving voice
calls---is where AMD has a genuine opening:

\begin{itemize}[noitemsep]
  \item 25--40\% lower cost per token for LLM inference.
  \item 192\,GB HBM3 on MI300X fits 70B models on a single GPU.
  \item Pure PyTorch TTS (Kokoro, Chatterbox) works on ROCm today with no code changes.
  \item MI355X within single-digit percentage points of B200 on server inference (MLPerf 6.0, April 2026).
  \item AMD--Meta 6\,GW production commitment signals ecosystem reliability.
\end{itemize}

The gap between ``AMD is an alternative'' and ``AMD is the gateway'' is
\textbf{three Docker containers, two Blueprints, one PyPI package, and one
TEI port}.  Beyond that, closing the four upstream gaps (fine-tuning
toolchain, ISV integrations, voice-plus-vision convergence, and synthetic
data pipelines) is what creates durable platform momentum.

\textbf{India is AMD's entry point.}  DPDP compliance demands on-premise
deployment; cost sensitivity demands lower CapEx than NVIDIA; 22 languages
demand Indian-language models (Sarvam, Gnani) that run on AMD; Sarvam's
\$234M raise and UIDAI partnership signal government intent to build on
sovereign infrastructure; AMD hardware cost advantage maps directly to
India's unit economics requirement.

The voice AI stack is five layers.  AMD is competitive in two today and
closing the gap in a third.  The strategic question is not whether AMD can
serve the voice AI market.  It is whether AMD moves fast enough to define
the on-premise, compliance-first, India-and-Asia stack before the market
standard calcifies around NVIDIA.
